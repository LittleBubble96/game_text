# 性能改动检查

运行 `python Tools/PerformanceChecks/run_checks.py`（需要 Python 3 和 .NET 9 SDK）。
脚本不依赖第三方包；使用生产代码里的答案索引实现，对照原来的排序匹配算法，
验证所有关卡的组合及随机选择、同组合多答案、重复索引、超过 64 笔、切关清理和热路径分配。
同时检查字形索引、分片、关卡覆盖及笔画索引范围。

## 字形数据维护

- `TextGraphicDataScriptableObject.asset` 现在是轻量索引，仅保存分片地址与字符目录。
- `Graphics/TextGraphics_001_025/` 等目录按 `Level_` 数据编号每 25 关划分。
- 每个分片独立目录，与 Configs 的 `PackDirectory` 规则配合；保持分片文件名唯一。
- 同一字只存一份，归入最早使用它的关卡段。尚未分配关卡的字放入 `TextGraphics_Unassigned`。
- 原来的字形生成、重新生成、关卡编辑预览已适配索引；新增字形先进入未分配分片。
- 分配关卡或调整顺序后，可执行 Unity 菜单 `Tools/关卡/按25关重建字形分片`。
- 运行时最多保留最近两个分片的加载句柄，淘汰时 Dispose；实际底层 Bundle 的回收时机由 YooAsset 管理。
- 已显示的字额外保留一份托管字形引用，避免异步切关淘汰缓存影响全选操作。
- 新资源需要由 Unity 导入，并在下次资源构建时一起打包；不能仅替换旧版本的主索引。

## Unity / 真机验证

1. 首次启动后进入保存的关卡，确认答案槽齐全、位置与点击正常。
2. 连续跨三个分片切关，再返回第一段；检查字形重新加载、全选、提交及引导。
3. 快速返回主页、再次进关，检查旧请求不覆盖新关卡，槽动画没有残留。
4. 打开结算界面静置，确认弯曲标题样式保留，Profiler 中不再每帧执行 WarpText。
5. 同一笔画组合对应多个答案时，多次提交仍按原顺序找到各答案；全部找到后才提示重复。
6. 检查对象池预热、回收、过期释放后，场景实例及资源引用没有持续增长。

命令行验证不替代 Unity 资源导入、Bundle 构建和真机帧耗时测量。
