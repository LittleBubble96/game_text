# 微信关卡上报

事件 ID：`10000003`（`level_incident_report`）。调用链为 `BiMgr → SDK → SdkSession → ISdk → WXSDK → WX.GetMiniReportManager().Report(json)`。当前项目微信 Unity SDK 已提供接口，无需修改包或增加 JS 桥接。

## 已确认范围

- 动作：成功 `1`、进入 `5`、退出 `6`、使用道具 `7`。
- 不接失败、重试、复活、广告激励 `8`、分享 `9`；不发送 `externInfo`。
- 现有自定义 BI 继续保留；这里新增微信标准关卡上报，不替代 `WX.ReportEvent`。

## 字段

| 字段 | 口径 |
| --- | --- |
| eventID | 字符串 `10000003` |
| levelID | 实际关卡 ID，整数 |
| levelName | 实际关卡配置名称，字符串 |
| levelAction | 主线关卡，整数 `1` |
| levelResult | 仅 `1/5/6/7`，整数 |
| levelProgress | 已找到答案数 ÷ 通关所需答案数 × 100，向下取整并限制在 0～100；通关为 100 |
| gameVersion | `Application.version` 的 `major × 10000 + minor × 100 + patch`；`2.0.8 → 20008`，未知或无法无歧义映射的版本为 0 |
| levelTime | 仅成功事件携带；本次进入至通关的有效前台时间，整数秒，向下取整 |
| loginCount | 仅进入事件携带；当前关卡累计进入次数，首次为 1；通关推进下一关时清零 |

数字在 JSON 中保持整数；非适用事件不携带 `levelTime`、`loginCount`，也不携带自定义 BI 的公共字段。

## 触发与状态

- 有效关卡实际启动才记录进入；配置预览和 GM 只切换数据不触发。首页进入、下一关和恢复关卡均计为一次进入。
- 手动通关与下一关道具通关共用成功入口，每次进入最多成功一次；通关后返回首页不补报退出。
- 未通关返回首页上报退出。切后台只暂停计时；强杀进程不保证产生退出事件。
- 提示与下一关道具实际生效才报使用道具；支付失败、广告中断、免费全选/清空选择不报。下一关道具补齐答案后，道具事件进度已为 100。
- 广告展示成功后暂停标准关卡计时，关闭、中断、失败、超时或离开页面结束广告流程时释放暂停。后台与多个广告请求的暂停取并集，防止重复扣时或提前恢复。广告预加载不暂停计时。
- 标准计时在每次进入重置，不跨重进累计；恢复关卡保留实际答案进度。
- 仅在当前关卡存档 `CorePlaySaveData.enterCount` 记录进入次数；进入时只更新内存，不额外调用 `Save()`，随原有存档流程顺带保存。同一关重进累加，通关推进下一关时清零。普通答案保存保留次数，不保存任何历史关卡次数列表。旧存档缺失字段按 0 处理，下一次进入报 1；清档后同样重新计数。
- `RecordLevelEntry()` 不接收关卡 ID，只更新 `enterCount`；不调用 `SetCurrentLevel`、不初始化业务存档、不触发关卡推进。业务关卡 ID 由原有流程维护。`SetCurrentLevel` 保留原来的 ID 赋值行为，`SaveCurrentProgress` 保留原来的答案及快照保存行为；答案与快照清空仍由原有 `AdvanceToNextLevel` 流程负责。

## SDK 与验证

标准事件以不可变快照进入现有登录门禁、512 条 FIFO 队列及同步异常有限重试。补发不重算次数、进度和用时。返回接收成功表示已进入本地队列，不代表微信后台确认收件；当前 Unity SDK 的 `Report(string)` 不提供逐条报告的异步结果回调。开发构建启用组件 debug，正式构建关闭。

- `Tools/Test-LevelReporting.ps1`：字段类型与省略规则、动作范围、计时暂停重叠、状态去重、存档次数、登录缓存及重试、真实 BiMgr 触发口径。
- `Tools/Test-StartupSdk.ps1 -UnityData <Unity Editor Data目录>`：原 SDK 登录与启动事件回归。

上线前需重新构建播放器与热更程序集（新增了 GameSDK 常驻 API），并在微信真机检查事件 `10000003` 的实际接收、前后台回调和广告播放期间计时。
